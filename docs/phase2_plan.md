## 2. The originality rule (new)

Goal: the finished video reads as our own retelling. A viewer, or the source's author, should find nothing that says it came from that book.

**Principles**
1. Facts and events are not owned by a book; the author's expression is. We retell events in our own structure, wording, titles and examples.
2. The source is evidence for us, not a character in the video. The narration never says "the author", "the book", "the chapter", "as the text explains", "according to", a page number or a publisher.
3. The Phase 1 evidence stays internal. It is how we fact-check, and it is never rendered.
4. Where a story depends on facts only the book gives, the story goes into research (`research_questions` already exists): we verify with independent public sources and cite those internally. A story we cannot verify independently is held back or marked unverified, not published on the book's word alone.
5. Book figures and charts are not reused. Rights flags from Phase 1 become a hard rule: a flagged figure is a reference for what to build, not an asset. Charts are rebuilt from verified numbers later.

**How it is enforced in the product**
- The Phase 2 JSON has two separate parts: `public` (narration, on-screen text, scene prompts, titles) and `evidence` (references, quotes, figure ids, source metadata). Nothing from `evidence` is allowed inside `public`.
- A **source-leak validator** runs on every narration segment, on-screen text and compiled prompt. It fails approval when it finds: the book title or author name, "chapter", "the author", "this book", "page N", publisher or credit names (for example the eSignal credit), a verbatim quote from the source, or a run of 6 or more consecutive words that also appears in the cited passages (configurable).
- **Originality of treatment** (one of the scored dimensions) gets a measured part: n-gram overlap between our narration/titles and the source passages, plus a check that titles are not the source's own wording. Story titles such as "The FedEx Gap" are treated as working titles and renamed in the plan.
- Quotes are off by default. A short quotation, if the editor wants one, needs an explicit per-segment decision and a recorded rights note.
- People, companies and events keep their real names (those are facts). A company's trademark use in imagery follows the normal rules for editorial content; image prompts avoid logos unless the editor decides otherwise.
- This is a product policy and a safeguard, not legal advice. Before monetised publication, rights for any person likeness, brand or third-party material still need a human check. The licence checklist covers model weights; a separate publishing checklist is added to the export.

## 3. Implementation plan

New package `story2/` (keeps Phase 1 untouched; shares `db`, `llm`, `tokens`, `settings`, `eta`, `pipeline` helpers). Tables added by migration: `plans`, `segments`, `scenes`, `assets`, `plan_revisions`. Stages are tasks in the existing `tasks` table, so everything resumes after a restart and feeds the learned ETA.

### Batch A: contracts and narrative
- `story2/intake.py`: load an approved story and its evidence pack from Phase 1 with no re-entry; readiness check (nature must be story or anecdote unless the editor overrides, outcome present, dates stated, no unverified quotes behind key claims, independent verification status). Missing evidence is flagged, never invented.
- `story2/blueprint.py`: narrative blueprint (viewer promise, central question, opening, context, conflict, turning point, payoff, ending) with selectable structures (cold open, mystery, decision and consequences, problem-mechanism-example, myth-evidence-correction, multi-case, question-driven). Model proposes; editor picks.
- `story2/narration.py`: Hindi (Devanagari) segments with plain text, Svara-annotated text, emotion + strength, pace, emphasis, pronunciation notes, estimated duration, evidence ids, linked scene ids, status. Emotion map to the labels read from the live voices endpoint.
- `story2/leak.py`: the source-leak and overlap validator from section 2.
- Tests: fixtures for a documented narrative, a technical explainer and a weak anecdote; tag validation; tags kept out of plain text; edits to one segment do not change another; leak validator catches each pattern.

### Batch B: storyboard
- `story2/scenes.py`: canonical scene record (all fields in the brief), kept separate from any provider payload. Factual fields (place, period, objects) are marked `fixed_by_evidence`; creative fields (camera, light, palette) are marked `creative`.
- Timing from narration duration estimates; alignment of scenes to segment ids that survives edits.
- Visual taxonomy (the 16 types in the brief), each scene with a narrative purpose and a "what is new for the viewer" line; a repetition check for adjacent compositions.
- `story2/registry.py`: continuity registry for people, places, props, styles with fictionalisation status. Real people are never given an invented likeness presented as authentic.
- Separate plans for 16:9 and 9:16; verticals are composed, not cropped.

### Batch C: model-aware prompts
- `story2/providers/base.py`, `qwen.py`, `flux.py`: adapters with a declared capability set (negative prompt, edits, reference count, size limits, transparency), read from configuration and verified by a probe.
- Qwen compiler: the 12-part brief order, positive explicit language, left/centre/right placement for key compositions, exact text only when required. FLUX compiler: its own natural-language ordering. Both preserve the same canonical scene and constraints.
- Optional prompt-enhancer step if it exists; original and rewritten prompts both stored; the rewrite is validated against the canonical scene (names, dates, counts, exclusions) before use.
- Reference/edit plan limited to 3 images per scene, "change X, keep Y" instructions.
- Comparison view: both compiled prompts for one scene; optional explicit preview action (one image, async, records model, prompt, parameters, seed, result), isolated from plan creation.

### Batch D: review and export
- Editorial UI tab: segments and scenes side by side, approve/reject/revise/lock/reorder/regenerate per item; regeneration never overwrites approved or locked work.
- Scoring: the twelve dimensions in the brief, each with a reason and an action; no single score.
- Versioned JSON export with a JSON Schema, `public` / `evidence` split, revision history, licensing metadata.
- Full regression run including all Phase 1 tests.

After each batch: run the tests, report files changed, results and limits, and stop if acceptance criteria fail.

## 4. Decisions (owner, confirmed)
1. **Quotes:** none by default. Narration is written in our own words; no sentence is copied from the source. A spoken quotation from a person in the story (on the public record) is allowed only as an explicit per-line choice with a recorded rights note.
2. **Independent verification:** stories that only the source supports are **not blocked**. They proceed with an "unverified" mark on the plan, and the research questions stay attached so they can be checked later.
3. **Narrator:** first person, voiced by a generated avatar whose name will be set later. The name is a plan-level setting (placeholder `{narrator}`), so it can be filled in without touching the narration. Rules for first person: "I" guides and reacts ("let me show you", "here is what surprised me"); it never claims to have been present at, or personally involved in, events from the story, and never invents personal experience. The avatar is registered as a continuity asset (appearance, wardrobe, setting) with status "to be designed"; creating the avatar itself is outside this module.
4. **Format:** long-form 16:9 only for the first build. The 9:16 plan type stays in the schema but is not built until long-form is accepted.

## 5. Risks
- The gateway serves one request at a time, and image and text models take turns on the GPU. A full plan with previews will take a while; previews stay opt-in.
- Svara emotion strength differs by voice and is unverified until sampled; defaults are chosen after listening tests, not before.
- Hindi narration quality from the local 12B model is untested. A short Hindi sample test is the first task of Batch A.
